# M3 final episode integration plan

12 November 2026 · Scope: Chapters 1–6, existing local episode only.

The owner authorised a fresh end-to-end playthrough, fixes to transitions, controls, checkpoints and measured performance, and a complete browser review. No M4 accounts/services, new chapters, deployment or Git publication are included.

## Implementation order

1. Inspect the six coordinators, shared input/save contract and earlier chapter tests. Preserve frozen candidates and record a separate integration build.
2. Replace obsolete outline/review wording in the normal episode entry and handoffs. Retain explicitly isolated chapter previews. Preserve objective order, the actual preparation inventory, lethal-attack-only defeat and battle-entry retry.
3. Exercise one new normal browser run from an empty browser context. Earn every objective through real keyboard/pointer interactions and complete cinematics at normal speed. Record chapter handoff identity/revision, screenshots, resource loading and frame pacing. Exercise interruption/reload, a practice miss, movement, a telegraphed attack, defeat/retry, completion and replay. Do not seed this journey or manipulate animation clocks.
4. Reproduce and fix defects found in that run. Rerun affected checks, then the final full route if a change affects progression. Run targeted save/stale/cancellation checks and portrait/landscape touch checks on the final production build.
5. Profile fresh Chrome processes without competing automated game browsers. Distinguish local loading, encoded bodies and actual hosted transfer. Investigate measured bottlenecks before changing rendering budgets. Report unmet targets and device limitations honestly.
6. Freeze the final candidate with hashes, publish the local evidence/handover and open the normal episode entry in the visible browser for owner playthrough.

## Acceptance and evidence

- All twelve ordered objectives earned in one fresh normal run, with one run ID across six chapter handoffs. No review shortcuts or injected checkpoints in this primary journey.
- Movement and interaction restore after cinematic/pause; practice can miss and be retried; battle supports movement/aim/dodge, lethal defeat and retry without replaying preparation.
- Reload resumes the last confirmed checkpoint; unfinished actions are not credited. Completion persists; replay creates a fresh run and retains prior completion history.
- No uncaught browser errors or failed required resources in the completed journey. Portrait and landscape Chrome touch emulation remain playable without overflow or overlapping essential controls.
- Actual startup, resource bytes and frame-time distributions recorded with the hardware/browser and test boundaries. The proposed 30 FPS floor and 60 FPS desktop goal are targets, not assumed passes.
- Final build served locally and opened for owner review. Physical phone GPU/heat, Safari, hosted delivery, cloud accounts and unaided enjoyment remain separate, unverified outcomes.
