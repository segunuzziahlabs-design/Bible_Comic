# MSR-03: speech and reactions pilot

20 November 2026. Follows the [MSR plan](motion-speech-and-guided-routes-plan.md) and [verified MSR-02 candidate](../quality-review/msr02-motion-foundation.md). This phase polishes the canonical Chapter 4 David–Saul audience; it does not add walking connections or change the battle.

1. Capture the current audience in the browser. Audit every dialogue recording against its metadata and mouth envelopes. Measure the pilot's speech/mouth/caption timing and audio routing, and inspect sustained gestures, listeners and camera transitions. Source risks are not reported as observed defects until checked.
2. Owner clarification: **improve intonation**, with no particular faulty line identified. Prepare a three-line performance sample with the same existing David/Saul voice identities and words, using deliberate sentence phrasing and measured pauses through the already installed local generator. Keep the original recordings for comparison, regenerate mouth cues from the final waveforms, and record settings/licences/hashes. Owner listening determines whether intonation is better. Replace the pilot's backward/repeated/held gesture patterns with forward, line-specific gestures and listener beats using the existing rig. Preserve armour/stone/throw timings and MSR-02 movement.
3. Where demonstrated, correct technical envelope/timing faults and introduce an opt-in cinematic dialogue mix that remains clear across camera cuts while environmental sound stays spatial. Keep mute/pause/reset/disposal under the existing audio owner. Validate asset metadata early with useful errors.
4. Test the pilot with actual browser input in desktop, portrait and landscape: one Speak, correct speaker, complete lines, silence closure, listener reactions, pause/resume, tab return, restart cancellation, mute and returned movement. Record screenshots, rig/mouth/audio traces and a played sample for owner listening review. Compare with the frozen MSR-02 build.
5. Run checks appropriate to any shared speech changes, including Jesse/camp regression and a fresh six-chapter run if the common runtime is modified. Record verified results, remaining listening decisions and the next phase in a report and the defect register. Show the pilot in the browser.

Exit: technical timing and lifecycle checks pass; no new progression, prop or control regression. Owner approval of pronunciation, emotion and overall speech quality is explicitly separate from analyser/pose evidence. The requested three-line intonation revision uses the existing synthetic cast; no new service subscription, dependency, schema, authentication configuration, deployment, commit or push is implicit in this task.

Proposed timing targets retained from the MSR plan: mouth/caption/voice cue alignment within 100 ms and mouth closure within 150 ms of a line ending or sustained silence. Measure relative to the browser audio clock; physical output latency and subjective delivery are not inferred from logs. The MSR-02 planted-foot/input-latency gap remains recorded and is not silently closed by this speech pass.
