## Implementation and reproduction

The [asset register](../assets/asset-register.md) records original geometry, animation and generated audio, scale/axes, GLB costs and regeneration commands. No third-party model, texture, recording or purchase was used. David and Jesse share a temporary shepherd model; this does not establish final portrayal or episode art quality.

The root project starts [courtyard_proof.tscn](../../scenes/proof/courtyard_proof.tscn). Proof-specific scripts separate player, input, actor animation, UI and guarded state. Draft text and world assembly remain in the proof controller; a reusable data-driven episode implementation remains Phase B/C. The separate `Web` preset retains the A03 toolchain fixture; `ProofWeb` exports the interactive scene in single-thread Compatibility mode.

```powershell
.\tools\godot.ps1 --headless --path . --script tests/proof_checks.gd
.\tools\export-proof.ps1
python .\tools\serve-proof.py
```

Use Python 3.12+ for the server. Open `http://127.0.0.1:8060/`; append `?diagnostics=1` for read-only measurements. The server defaults to loopback and permits only generated web files, with correct WASM MIME, gzip, HTTP/1.1 and cache revalidation. No firewall, public hosting or production settings were changed. The [device checklist](a04-device-test-checklist.md) describes a deliberate owner-run private-network test.

The export command imports, exports, checks the actual PCK for dependencies/source exclusions and writes compressed files plus a manifest in `build/proof/`. It treats logged engine errors as failures even if the process returns zero. Generated builds/cache are ignored; editable assets, import settings and code are retained.

Browser tests use a Playwright installation supplied by the environment, without adding project dependencies:

```text
node tools/browser-proof-check.cjs <absolute-playwright-module-path> chrome desktop
node tools/browser-proof-check.cjs <absolute-playwright-module-path> msedge desktop
node tools/browser-proof-check.cjs <absolute-playwright-module-path> chrome touch
node tools/browser-load-check.cjs <absolute-playwright-module-path>
```

Journey tests send keyboard, mouse and Chromium touch events. Diagnostics only report state/layout; there is no teleport, objective setter or bypass API. Movement follows a reachable route around the table. Expected radio/network timing differs from these local automated checks.

Compressed JS + WASM + PCK total: **10,402,554 bytes** (about 10.40 MB), excluding HTML/audio worklets. The PCK is 73,404 bytes uncompressed; the engine WASM is 39,514,754 bytes uncompressed / 10,263,606 bytes gzip. File bytes are not total browser memory.

“Cold-context” means a new browser context/cache, not a cold OS/GPU/engine process. Later contexts reuse process-level caches; the first usable-scene observation is the relevant warning, not the fastest later number. Warm reloads still report roughly 10.26 MB transferred for the core resources, dominated by WASM, so they are not a zero-download/offline result. The slower-network run is desktop Chromium simulation at 10 Mbit/s download and 150 ms latency, not an actual mobile connection. See chrome-loading.json for raw resource timing.

The browser host is Windows 11 Pro 10.0.26200, Intel N150, approximately 15.8 GiB RAM. Browser diagnostics report ANGLE / Intel Graphics / Direct3D11, rather than a forced software renderer. Tests ran headlessly under automation; remote-display scheduling, shader compilation and the host environment can affect results. This is not the proposed 4 GB laptop or a physical 2 GB phone.

Thirty steady-state samples per journey run are taken once per second **after switching to Extra light**, not a complete-frame benchmark. The `frame_ms` field is Godot `Performance.TIME_PROCESS × 1000` (CPU process monitor), not end-to-end GPU frame time or a percentile of every rendered frame. Cold-start stalls and micro-stutter cannot be judged from the steady FPS range alone. Numerical acceptance remains open under DEC-09/10.

Audio evidence is a running Web Audio context and started source nodes after a real input gesture, without disabling autoplay policy. Physical speaker audibility, iOS silent-mode behavior and remote HTTP/HTTPS restrictions are not established. Focus tests disable Playwright's forced focus emulation and confirm `document.hasFocus() === false` before returning. Real mobile background suspension remains untested.

## Defects found and corrected

| Finding | Correction / verification |
|---|---|
| Local HTTP/1.0 script transfer reset in tested browsers | Restricted server uses HTTP/1.1; subsequent engine/asset requests succeed with gzip |
| Scene-only export omitted script-loaded dependencies | Export all runtime resources with explicit source exclusions; PCK dependency loading check now fails exports with missing runtime files |
| Initial animation test sampled a crossfade instead of the clip | Pose test samples Walk directly; changing bone rotation and looping are verified |
| Reopening the saved Blender file discarded unused Walk/Wave actions | Retain all actions with fake users; source reopen confirms all three. Regenerated runtime GLB/audio SHA-256 values match the browser-tested assets |
| PowerShell consumed the Python argument separator in a regeneration command | Dedicated `create-proof-assets.ps1 -Overwrite` forwards a native argument array; generation and source reopen checked |
| Touch GUI and world gestures could conflict | GUI uses touch-to-mouse adaptation; world look ignores emulated mouse events and tracks separate fingers |
| Cancelled touch could reacquire movement | Cancel guards plus release/reset tests; browser multi-touch cancellation exercised |
| Narrow-screen action button clipped; guidance overlapped movement control | Compact font/placement and tested portrait/landscape layouts |
| Extra light did not reduce cost on already-small CSS viewports | Also limits 3D scale to 0.75; measured reduction while UI remains at CSS size |
| Browser focus loss did not reliably pause through the engine notification alone | Retained JS blur/visibility callbacks and explicit held-input clearing; desktop focus test passes |
| Stable local build filenames could retain stale cache entries | Assets revalidate; HTML is not cached. Production host versioning still needs F02 |

Browser callbacks follow the official [JavaScriptBridge callback contract](https://docs.godotengine.org/en/stable/classes/class_javascriptbridge.html?highlight=javascript), including retaining the callback reference. This is implementation guidance; the saved browser reports are the runtime evidence.

## Remaining limits and next gate

1. Physical Android Chrome and iPhone Safari, lower-memory hardware, browser bars/notches, thermal/memory pressure, mobile audio and tab suspension require the [device checklist](a04-device-test-checklist.md). There are no participant results yet.
2. The proof omits the route, battlefield, sling encounter, final ending, production checkpoint schema and complete-episode content. Safe-spawn fallback code exists but forced-fall recovery was not exercised in the browser. Loading-failure guidance is implemented; exhaustive offline/retry testing remains open.
3. Final art/detailed dialogue, browser/OS support floor, performance/load thresholds, capacity commitment and hosting remain owner decisions. No deployment or release gate passed automatically.
4. The engine payload dominates the small scene. Measure phone launch before adding content or considering a custom engine build. Full episode profiling is still D04/D05; a tiny PCK does not establish low total browser memory.
5. Do not convert this proof into a promised two-week complete episode. Retain 10 November as a conditional candidate target and 30 November as the release decision; reforecast after physical-device results and available daily capacity are known.
