## Implemented

Responsive landing, public chapter catalog, Clerk components, dashboard, player profile/settings, appearance choices, episode results and completed-chapter revisits. Landing does not load PlayCanvas, GLB models or chapter audio. Previous character preview is preserved as `david-preview.html`.

The cloud adapter uses the existing episode-session boundary. It submits semantic start/objective/defeat/retry/replay commands, accepts canonical server checkpoints, checks revisions and retains command IDs on retry after lost responses. It does not upload arbitrary progress snapshots or fall back to local saves while claiming cloud confirmation. Twelve ordered objectives, six chapters, lethal-defeat-only failure, battle retry and replay history remain intact.

The applied [SQL migration](../../apps/playcanvas/supabase/migrations/202611170001_game_accounts.sql) includes verified-token subject ownership, private profiles/settings, versioned catalog, run history, battle attempts and transactional command receipts. Row locking serializes competing commands. RLS and restricted RPC grants are included. It was applied through the SQL editor to the confirmed development project; no CLI migration-ledger registration is claimed. A later attempted read-only verification was appended by the virtual editor and tried to repeat the migration, producing a relation-already-exists error; the original schema remained installed. Actual hosted API tests below verified the resulting functions and ownership rules.

Account gates run before chapter initialization, including direct review URLs. Account changes redirect away from an owned session. Save errors retain the confirmed checkpoint; stale settings offer **Reload saved settings**. Cloud responses have a 20-second deadline and retry preserves the command ID. Local appearance import is explicit. Sound/control overrides persist across chapter pages in the current tab and are isolated by profile and settings revision; account defaults require Save settings. The Dashboard link flows within the game header instead of covering chapter titles. A confirmed earlier episode completion retains chapter-revisit access after replay starts a fresh run; revisits leave the normal checkpoint unchanged.
