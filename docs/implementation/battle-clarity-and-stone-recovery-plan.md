# Battle clarity and individual stone recovery

24 November 2026. Approved in the preceding discussion. Extend the existing Chapter 5 battle; preserve the six chapters, real hit/miss collision, continuous attacks, final sword action, authentication and checkpoint formats. No deployment or push is included.

1. **Readable projectiles and aiming.** Improve stone/trail contrast and screen size, trajectory beads and forehead marker. Make a small framing adjustment while retaining David, Goliath and the incoming spear. Display aids must not enlarge collision targets or steer throws.
2. **More forgiving spear pacing.** Start with 2.1 seconds of flight and 4.8 seconds of recovery during sling combat. Preserve the existing arc shape through time scaling; use the same slower projectile sample for drawing and swept collision. Keep warnings, lethal contact, movement, aiming and dodging active. Blend back to ready after the throw rather than replaying the release pose during recovery.
3. **Five-stone lifecycle.** Track held, airborne, landed and spent stones by stable ID. Deduct at release, retain every miss's landing position and prevent duplicate recovery or more than five held stones. Catch misses at arena barriers and choose reachable nearby ground for obstructed impacts. Replace automatic bulk refill only in the current cinematic battle; keep historical prototype behaviour isolated.
4. **Player-directed recovery.** Add Collect stones / R, highlighted at zero ammunition and available with a partial pouch. It activates the existing route arrow to the nearest landed stone; it does not walk David automatically. Stop close to a stone for a short automatic, interruptible pickup using the retained animation. Movement, jump, dodge and throwing cancel pickup without granting a stone. One recovered stone can be thrown immediately; collecting all five is optional. Goliath continues attacking throughout.
5. **Verification.** Run focused rules tests for timing, collision, inventory conservation, reachability, cancellation, pause and retry; then actual production-browser tests in desktop, portrait and landscape. Exercise five real misses, no bulk brook refill, per-stone guidance, one-at-a-time throw/recovery, collect-all, interrupted pickup, real spear defeat, Retry, a genuine forehead hit and the existing final action/Victory. Inspect screenshots and measure representative frame pacing. Record actual results and limitations in a separate dated report; keep the previous QA workbook as its historical snapshot.

Stone positions and pickup progress remain battle-attempt state, like existing ammunition. Reload/Retry uses the existing battle checkpoint and resets that attempt's five stones. No database migration or additional save event is needed.
